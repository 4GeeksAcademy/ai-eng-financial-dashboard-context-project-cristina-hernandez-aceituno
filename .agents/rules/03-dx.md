# 🎯 Reglas de Developer Experience (DX)

Reglas sobre herramientas y procesos para desarrolladores.

---

## REGLA-DX-001: npm Scripts Estándar

**Norma**: Frontend expone scripts estándar para dev, build, lint, test.

**Hecho citado**: `frontend/package.json` (CONCRETE_FINDINGS.md, línea 149)

```json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc -b && vite build",
    "lint": "eslint .",
    "test": "vitest run",
    "test:watch": "vitest",
    "test:coverage": "vitest run --coverage"
  }
}
```

**Por qué**: 
- Developers esperan `npm run dev`, `npm run build`, `npm test`
- Consistencia con estándares de la industria
- Fácil onboarding

**Aplicación**: 
- Mantener estos scripts
- No cambiar nombres
- Documentar nuevos scripts si los agregás

## REGLA-DX-002: TypeScript Strict Mode Habilitado

**Norma**: Frontend tiene TypeScript strict mode activado.

**Hecho citado**: `frontend/tsconfig.app.json` (CONCRETE_FINDINGS.md, línea 160)

```json
{
  "compilerOptions": {
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noFallthroughCasesInSwitch": true
  }
}
```

**Por qué**: 
- Detecta errores en tiempo de compilación, no en runtime
- Mejora calidad del código
- Evita bugs silenciosos

**Aplicación**: 
- No desactivar estas flags
- Resolver errores TypeScript antes de commit
- Si hay muchos errores, refactoriza en lugar de silenciar

## REGLA-DX-003: Hot-Reload Automático

**Norma**: Tanto frontend (Vite HMR) como backend (Uvicorn reload=True) tienen hot-reload.

**Hecho citado**: 
- Frontend: Vite automático en `vite.config.ts`
- Backend: `backend/app/main.py` con `reload=True` (CONCRETE_FINDINGS.md, línea 309)

**Por qué**: 
- Feedback inmediato al cambiar código
- Desarrollo ágil y responsivo
- Mejora productividad

**Aplicación**: 
- No desactivar en desarrollo
- Usa en producción con `reload=False`
- Verificar que se actualiza cuando cambias código
